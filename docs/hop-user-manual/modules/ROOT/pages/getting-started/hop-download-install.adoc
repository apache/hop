= Download and install Hop

Hop is designed to be as easy and accessible to use as possible.
There is no installer and no server to set up: download, unzip, start.

== Check your Java

Hop is self-contained. The only thing it needs is a Java runtime.

The official Java version for Hop is **21**.

[source,shell]
----
java -version
----

You should see something like:

[source,shell]
----
openjdk version "21.0.10" 2026-01-20
OpenJDK Runtime Environment (build 21.0.10)
OpenJDK 64-Bit Server VM (build 21.0.10, mixed mode, sharing)
----

If that command is not found, or reports an older version, install a Java 21 runtime first.
See xref:supported-jvms.adoc[Supported Java Versions] for which runtimes are known to work, and which one to avoid.

== Download and unzip

Download the client from the https://hop.apache.org/download/[Apache Hop downloads page] and unzip it to a folder of your choice.

That folder is your Hop installation.
Everything you need is in it:

[options="header"]
|===
|What|Where
|The launcher scripts|`hop`, `hop.bat` and the individual `hop-*.sh` / `hop-*.bat` scripts
|Configuration|`config/`
|Plugins|`plugins/`
|Projects created for you|`config/projects/default` and `config/projects/samples`
|===

== One step worth doing now

By default Hop keeps its configuration inside the installation folder.
That means an upgrade - a new unzip - leaves your projects and settings behind in the old folder.

Point Hop at a user-level configuration folder instead, once, before you start:

[tabs]
====
Windows::
+
--
[source,shell]
----
hop.bat setup apply --defaults
----
--

Linux, macOS::
+
--
[source,shell]
----
./hop setup apply --defaults
----
--
====

Restart Hop afterwards.
You can do the same thing from the GUI later with *Tools -> Configure Hop environment...*.

See xref:hop-tools/hop-setup.adoc[Hop Setup] for what it changes and how to undo it.

== Start Hop Gui

[tabs]
====
Windows::
+
--
[source,shell]
----
hop-gui.bat
----
--

Linux, macOS::
+
--
[source,shell]
----
./hop-gui.sh
----
--
====

The first start takes a little longer than the ones after it, because Hop scans and registers its plugins.

|===
|Option|When you'd use it|Read more

|Docker - `apache/hop`

|Docker - `apache/hop-web`
|Hop Gui in a browser, for shared or hosted development environments.
|xref:hop-web-docker.adoc[Hop Web in Docker]

|Hop Web
|The same Hop Gui, running in a browser instead of on your desktop.
|xref:hop-gui/hop-web.adoc[Hop Web]
|===
