= Apache Airflow Workflow Engine

The Apache Airflow run configuration runs a workflow on Airflow from Hop GUI or `hop run`:

. It publishes the project as a DAG bundle, as xref:hop-tools/hop-airflow-bundle.adoc[hop airflow-bundle] with `--target` does.
. It waits until Airflow shows the DAG of the workflow as it was just published, and unpauses it when it is paused and has no schedule.
Airflow reads a changed file again every 30 seconds by default (`min_file_process_interval`).
. It starts a DAG run. The workflow's parameters become the run conf.
. It follows the run until it ends: the logs of the tasks appear in the log of the workflow, and the canvas shows which actions run and how they ended.
. Stopping the workflow in Hop GUI fails the DAG run, which makes Airflow stop the running tasks.

The result of the workflow is the outcome of the run in Airflow, with the counters of the task that ended last: as in Hop, each action passes them on to the next.
Each action of the workflow is a task in Airflow (see xref:hop-tools/hop-airflow-bundle.adoc#_tasks[Tasks]), unless *Tasks* asks for one task for the whole workflow.

Airflow must already read the bundle folder as a DAG bundle, and its workers must have Hop and a Java coordinator: see xref:hop-tools/hop-airflow-bundle.adoc#_set_up_airflow[Set up Airflow].
The run configuration publishes the files of the project as they are saved, so save the workflow before you run it.

This page describes the options that are specific to the Airflow workflow engine. These options extend the general xref:workflow/workflow-run-configurations/workflow-run-configurations.adoc[workflow run configuration options].

== Options

[options="header",cols="1,3"]
|===
|Option|Description

|Airflow connection
|The xref:metadata-types/airflow-connection.adoc[Airflow connection] to run the workflow on.

|DAG bundle folder
|The folder to publish the project to, and that Airflow reads as a local DAG bundle: a shared folder or a volume of the Airflow containers.
Publishing replaces what an earlier publish left there.
Leave it empty to write the stub into the project folder itself, for an Airflow that reads the project folder.

|Hop on the workers
|Where Hop is installed on the Airflow workers.
Default: `/opt/hop`, as in the Hop container image.

|Run configuration on the workers
|The workflow run configuration the workers run the workflow with.
Default: `local`.

|Environment files
|Configuration files of the project to use on the workers, relative to the project folder and separated by `;`.

|DAG id prefix
|The start of every DAG id.
Default: the project name followed by two underscores.

|Tasks
|One task per action, or one task for the whole workflow: see xref:hop-tools/hop-airflow-bundle.adoc#_one_task_for_the_whole_workflow[One task for the whole workflow].
The setting applies to every workflow in the bundle: a publish with another setting changes the DAGs of all of them.
An xref:metadata-types/airflow-dag.adoc[Airflow DAG] can set its own tasks.
Default: one task per action.

|Airflow DAG
|The xref:metadata-types/airflow-dag.adoc[Airflow DAG] to run, for a workflow that has more than one.
A workflow with one Airflow DAG runs that one, and a workflow without one runs the DAG it gets from the bundle.
For any other workflow this field is not used.
Parameter values you set for the run win over those of the Airflow DAG; a parameter you leave empty gets the value of the Airflow DAG.

|Unpause a paused DAG?
|Airflow can pause new DAGs, and a run of a paused DAG stays queued.
With this option the DAG is unpaused before the run starts; without it the workflow fails without starting a run.
A paused DAG with a schedule, from an xref:metadata-types/airflow-dag.adoc[Airflow DAG], is never unpaused: that would also start its schedule, and with catch up Airflow would start a run for every interval since the start date.
The workflow then fails without starting a run: unpause the DAG in Airflow when its schedule should start.

|Wait for a new DAG (seconds)
|How long to wait for Airflow to show the DAG of a workflow that was not published before.
Airflow parses the stub again every `min_file_process_interval` seconds (30 by default), and finds a stub in a new bundle folder after `refresh_interval` seconds (300 by default).
Default: 120.

|Check every (seconds)
|How often Hop asks Airflow for the state and the log of the run.
Default: 5.
|===

== Notes

* The log level of the run in Hop becomes the log level on the workers.
The canvas follows the actions through the lines Hop writes at the `Basic` level and higher, in English.
* Every publish replaces the bundle, and with it the DAGs of all workflows of the project.
For a bundle that is shared with others, use `hop airflow-bundle` and a Git DAG bundle instead.
* Clearing a task in Airflow runs its action again, with the result and variables of the tasks before it.
