= Hop Conf - The Hop command line configuration tool

Hop Conf changes the Hop configuration from the command line, so you can script what you otherwise do in Hop Gui: create projects and environments, set variables and change settings.

It writes to `hop-config.json`, in the folder of the `HOP_CONFIG_FOLDER` variable or by default in the `config` folder of your Hop installation, and to the configuration files of projects and environments.
Run it as `hop-conf.sh`, as `hop-conf.bat` on Windows, or as `hop conf` with the xref:hop-tools/hop.adoc[hop] command.

`hop-conf.sh -h` lists all the options of your installation.
Plugins add their own, for example for search, the File Explorer, linting, the AI Assistant or cloud storage.
The options described on this page are listed in <<_options,Options>>.

== Graph database connections

Hop Conf tests xref:metadata-types/graphs/graph-database-connection.adoc[graph database connections] and xref:metadata-types/graphs/neo4j-connection.adoc[Neo4j connections] by name, and tells what the graph database types support.
The connections come from the metadata of a project: enable it with the `-j` (project) or `-e` (environment) option of the `hop` command, before `conf`.
Without a project, and with `hop-conf.sh`, the metadata in the folder of the `HOP_METADATA_FOLDER` variable is used.
Variables in the connection settings are resolved with the variables of the project and environment.

[options="header"]
|===
|Option |Description

|`--graph-connection-test=<name>`
|Connect to the database and print what was tested, for example the URL. The exit code is 0 when the connection works, 1 with the error when it doesn't or when there is no connection with that name.

|`--graph-connection-info=<name>`
|Print the name, the metadata type (`graph-database-connection` or `neo4j-connection`) and the graph database type with its capabilities as JSON. Settings like the server or the password are not printed. A Neo4j connection has the type Neo4j.

|`--graph-database-types`
|Print all installed graph database types with their capabilities as a JSON array. This doesn't need a project or a connection.
|===

The same is available in Hop GUI: the *Test* button and the *Supports* line of the graph database connection editor.

[source,bash]
----
./hop -j my-project conf --graph-connection-test=memgraph
Graph database connection 'memgraph' is OK: bolt://localhost:7687

./hop -e my-environment conf --graph-connection-info=memgraph
./hop-conf.sh --graph-database-types
----

The JSON of a graph database type, also used for the `type` of `--graph-connection-info`:

[source,json]
----
{
  "pluginId" : "MEMGRAPH",
  "name" : "Memgraph",
  "description" : "Memgraph over the Bolt protocol",
  "documentationUrl" : "https://hop.apache.org/manual/next/metadata-types/graphs/graph-database-connection.html",
  "dialectId" : "MEMGRAPH",
  "queryLanguage" : "Cypher",
  "capabilities" : {
    "cypher" : true,
    "supportingConstraints" : true,
    "supportingIndexes" : true,
    "supportingNodeIndexes" : true,
    "supportingRelationshipIndexes" : true,
    "supportingRelationshipVectorSearch" : true,
    "supportingSchemaChangesInTransactions" : false,
    "supportingSchemaIntrospection" : true,
    "supportingShortestPath" : false,
    "supportingVectorIndexes" : true,
    "supportingVectorSearch" : true
  }
}
----

`queryLanguage` is `Cypher` or `Gremlin`.
The capabilities are listed in xref:metadata-types/graphs/graph-database-connection.adoc#_capabilities[Graph Database Connection].

== Options

The options described on this page.
Run `hop-conf.sh -h` for the complete list of your installation.

[%header, cols="1,3,4"]
|===
|Short option|Long option|Description

3+|*General*
|`-h`|`--help`|Displays the help message and quits.
|`-v`|`--version`|Prints version information and exits.
|`-l`|`--level=<level>`|The log level: NOTHING, ERROR, MINIMAL, BASIC, DETAILED, DEBUG or ROWLEVEL.

3+|*Projects*
|`-p`|`--project=<projectName>`|The name of the project to manage.
|`-pc`|`--project-create`|Create a project. Also specify its name and home folder.
|`-pm`|`--project-modify`|Modify a project.
|`-pd`|`--project-delete`|Remove a project from `hop-config.json`. Its files are not deleted.
|`-pl`|`--projects-list`|List the projects.
|`-ph`|`--project-home=<projectHome>`|The home folder of the project.
|`-pf`|`--project-config-file=<projectConfigFile>`|The configuration file, relative to the home folder. The default is `project-config.json`.
|`-pkf`|`--project-keep-config-file`|Keep the configuration file of the project if it already exists.
|`-pr`|`--project-parent=<projectParent>`|The parent project to inherit metadata and variables from.
|`-ps`|`--project-description=<projectDescription>`|The description of the project.
|`-pp`|`--project-company=<projectCompany>`|The company.
|`-pt`|`--project-department=<projectDepartment>`|The department.
|`-pv`|`--project-variables=<projectVariables>[,...]`|Variables of the project, as `variable=value` separated by commas.
|`-pa`|`--project-metadata-base=<projectMetadataBaseFolder>`|The metadata folder, relative to the home folder.
|`-pb`|`--project-datasets-base=<projectDataSetsCsvFolder>`|The data sets CSV folder, relative to the home folder.
|`-pu`|`--project-unit-tests-base=<projectUnitTestsBasePath>`|The unit tests folder, relative to the home folder.
|`-px`|`--project-enforce-execution=<projectEnforceExecutionInHome>`|`true` or `false`: check before execution that a workflow or pipeline is in the home folder of the project or a subfolder.
|`-pla`|`--project-list-action-types`|List the action types used in the project.
|`-plm`|`--project-list-metadata-types`|List the metadata types used in the project.
|`-plt`|`--project-list-transform-types`|List the transform types used in the project.
|`-plmi`|`--project-list-metadata-item-usages=<item>`|List the files of the project that use a given metadata item.
|`-xm`|`--export-metadata=<metadataJsonFilename>`|Export the metadata of the project given with `-p` to a single JSON file.

3+|*Environments*
|`-e`|`--environment=<environmentName>`|The name of the environment to manage.
|`-ec`|`--environment-create`|Create an environment. Also specify its name, purpose, project and configuration files.
|`-em`|`--environment-modify`|Modify an environment.
|`-ed`|`--environment-delete`|Remove an environment from `hop-config.json`. Its configuration files are not deleted.
|`-el`|`--environments-list`|List the environments.
|`-ep`|`--environment-project=<environmentProject>`|The project of the environment.
|`-eu`|`--environment-purpose=<environmentPurpose>`|The purpose of the environment: Development, Testing, Production, CI, ...
|`-eg`|`--environment-config-files=<file>[,...]`|The configuration files of the environment, separated by commas.
||`--environment-config-file-directory=<folder>`|A folder of configuration files. Matching files replace the configuration file list, together with `--environment-config-files` when that option is also set.
||`--environment-config-file-wildcard=<regex>`|Regular expression matched against the file names in that folder, for example `.*\.json`.
||`--environment-config-file-exclude-wildcard=<regex>`|Regular expression for file names to ignore in that folder, for example `.*secret.*`.
||`--environment-config-include-subfolders`|Also include matching files from subfolders of that folder.

3+|*Configuration files and variables*
|`-cfg`|`--config-file=<configFile>`|The configuration file to manage.
|`-cfv`|`--config-file-set-variables=<variable=value>[,...]`|Set variables in that file, separated by commas.
|`-cfd`|`--config-file-describe-variables=<variable=description>[,...]`|Describe variables in that file, separated by commas.
|`-sv`|`--set-variable=<variable=value>`|Set a variable in `hop-config.json`. Without a value, the variable gets an empty value.
|`-dv`|`--describe-variable=<variable=description>`|Describe a variable in `hop-config.json`.

3+|*Projects plugin*
|`-pn`|`--projects-enabled`|Enable or disable the projects plugin.
|`-py`|`--project-mandatory`|Make it mandatory to reference a project.
|`-ey`|`--environment-mandatory`|Make it mandatory to reference an environment.
|`-dp`|`--default-project=<defaultProject>`|The default project to use when none is specified.
|`-de`|`--default-environment=<defaultEnvironment>`|The default environment to use when none is specified.
|`-sp`|`--standard-parent-project=<standardParentProject>`|The parent project proposed when creating a project.
|`-sj`|`--standard-projects-folder=<standardProjectsFolder>`|The folder proposed when creating a project.
|`-dc`|`--default-projects-folder=<defaultProjectConfigFile>`|The configuration filename for new projects.

3+|*Graph database connections*
||`--graph-connection-test=<name>`|Test the graph database connection or Neo4j connection with the given name. See <<_graph_database_connections>>.
||`--graph-connection-info=<name>`|Print the graph database type and capabilities of a connection as JSON.
||`--graph-database-types`|Print the installed graph database types and their capabilities as JSON.
|===
