= image:transforms/icons/dbproc.svg[Call DB procedure transform Icon, role="image-doc-icon"] Call DB procedure

== Description

Call DB procedure runs a stored procedure or function once for every incoming row. With no incoming hop it runs once.

The call can return a scalar function value, `OUT` and `INOUT` parameters, and the rows of the procedure's first result set. Later result sets are read and discarded so procedure errors still surface. An empty first result set produces no output row for that input row. `OUT` values are copied onto every result row. `INOUT` values replace the incoming field of the same name.

A procedure that only returns a result set can also be called from xref:pipeline/transforms/tableinput.adoc[Table Input]. MySQL and MariaDB accept a `CALL` statement. Many other JDBC drivers accept the call escape:

[source,sql]
----
{call list_customers()}
----

PostgreSQL functions are usually read with `SELECT * FROM procedure_name(...)`. Use Table Input when the call is ordinary SQL and you only need the result set. Use Call DB procedure when the procedure needs `IN`, `OUT`, or `INOUT` arguments from the stream, or when you want one call per incoming row together with output parameters.

== Options

The dialog is split into *General*, *Parameters*, and *Fields* tabs.

=== General

[options="header"]
|===
|Option|Description
|Transform name|Name of the transform. This name has to be unique in a single pipeline.
|Connection|Database connection on which the procedure resides.
|Procedure name|Name of the procedure or function to call. Variables are supported.
|Find procedure|Lists the procedures JDBC reports for the selected connection. Some drivers return none; type the name when the list is empty.
|Enable auto commit|When auto commit is off, Hop commits once after the last row is processed.
|Result name|Name of the function return value. Leave this blank when the procedure has no scalar return. Ignored when the result type is Row; the stored name is kept if you switch back.
|Result type|Hop type of the function return value, or *Row* to output the rows of the first result set.
|===

=== Parameters

[options="header"]
|===
|Option|Description
|Name|Argument name. For `IN` and `INOUT` this is also the incoming stream field.
|Direction|`IN` (input only), `OUT` (output only), or `INOUT` (the incoming value is sent and replaced with the returned value).
|Type|Hop type of the argument. Output parameters need this so Hop knows what the driver returns.
|Get Fields|Button on the dialog. Fills the grid from the incoming stream and sets each direction to `IN`. Remove the rows you do not need.
|===

=== Fields

This tab is available when the result type is *Row*. The listed columns are appended to the incoming row, before any `OUT` parameters. Columns that are missing from the result set are null. Only the columns you list are added; an empty list still emits one output row per result row, with the incoming fields and output parameters.

[options="header"]
|===
|Option|Description
|Get fields|Reads the column names, types, format, length, and precision of the first result set, in the same way xref:pipeline/transforms/tableinput.adoc[Table Input] reads query fields. Hop asks the driver for callable-statement metadata first. When the driver has none, Hop executes the procedure with null values for `IN` and `INOUT` arguments, limits the read to one row when the driver allows it, and rolls the connection back when the driver allows that. A procedure that commits itself can still change data.
|Name|Output field name. Matched to the result-set column by label, then by name, ignoring case. Variables are resolved.
|Type|Hop type of the output field.
|Format|Optional conversion mask.
|Length|Field length. Empty means unspecified.
|Precision|Field precision. Empty means unspecified.
|===
