== Description

A sink that writes JSON documents with Beam's Elasticsearch bulk IO. It requires incoming rows and has no downstream row output. It is available only in Beam run configurations, not in the local Hop engine.
The sink does not create mappings or manage index lifecycle. Ensure the target index and privileges are appropriate before running.

== Options

All String settings support Hop variables, for example `${ES_HOSTS}` and `${ES_PASSWORD}`.
Variables are resolved while constructing the Beam graph. Empty required settings, unresolved variables and invalid configuration fail before submission; credentials must also be available on workers through the resolved graph.

[options="header"]
|===
|Option|Description
|Transform name|Unique name within the pipeline.
|Hosts|Required comma-separated HTTP(S) origins, for example `https://first.example:9200,https://second.example:9200`. Paths, URL credentials, query strings and fragments are rejected.
|Index|Required index. Input can use an index expression understood by Elasticsearch; output needs a writable target index.
|Document type (legacy)|Optional legacy type. See the version-specific limits below.
|Username / Password|Optional basic authentication; supply both or neither. Passwords are stored with Hop's password encryption convention; variable expressions remain expressions. This is not a substitute for restricting pipeline and runner access.
|JSON field|Required incoming String field containing one JSON object per row, default `json`. Null, empty, malformed and non-object JSON fail the pipeline. Multiline JSON is compacted to one line for the bulk protocol. Hop lazy String storage metadata is retained for conversion.
|Maximum documents per batch|Positive maximum bulk batch document count, default `1000`.
|Maximum batch bytes|Positive bulk batching byte threshold, default `5242880` (5 MiB). Beam may send smaller batches; one oversized document can exceed the threshold.
|===

== Delivery and errors

Beam generates the bulk index directives; the payload field is the document, not a user-supplied bulk directive.
Document IDs are generated by Elasticsearch. There is no explicit ID, upsert, delete or exactly-once setting in this transform.
Runner retries or reruns can create duplicates, so account for that in your pipeline design.
Bulk item failures fail the pipeline rather than silently discarding records. A failure can occur after other documents have already been persisted; there is no transaction rollback.
The Hop written metric counts successful bulk responses. Read/output metrics count rows extracted and submitted to Beam IO, not an exactly-once delivery guarantee.
