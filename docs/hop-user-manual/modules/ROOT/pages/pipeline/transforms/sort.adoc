= image:transforms/icons/sortrows.svg[Sort Rows transform Icon, role="image-doc-icon"] Sort Rows

== Description

The Sort Rows transform sorts rows based on the fields you specify and on whether they should be sorted in ascending or descending order.

The transform optionally only pass unique records, based on the sort keys.

TIP: You use can use multiple copies of the Sort Rows transform to speed up large sort operations. Make sure to add a xref:pipeline/transforms/sortedmerge.adoc[Sorted Merge] transform after the sort to correctly merge the streams of sorted that are generated by the various sort copies.

[WARNING]
====
On the Beam engines Sort Rows passes its rows on as they are, unsorted.
A Beam pipeline spreads rows over many workers and does not keep their order from one transform to the next, so a sort would be lost right after this transform.
xref:pipeline/transforms/mergejoin.adoc[Merge Join] and xref:pipeline/transforms/memgroupby.adoc[Memory Group By] don't need sorted rows on Beam, so a pipeline that sorts in front of them for the Hop engine runs unchanged on Beam.

With *Only pass unique rows* Sort Rows is refused on Beam: use xref:pipeline/transforms/uniquerowsbyhashset.adoc[Unique Rows (HashSet)] or Memory Group By instead.
A transform that needs its rows in order, such as xref:pipeline/transforms/groupby.adoc[Group By] with group fields, does not work on Beam either.
See xref:pipeline/beam/getting-started-with-beam.adoc#_unsupported_transforms[Getting started with Beam].

The native Spark engine does support this transform: it is mapped onto a Spark sort across the full data set instead of being run per partition.
====

== Options

[options="header"]
|===
|Option|Description
|Transform name|Name of the transform, this name has to be unique in a single pipeline.
|Sort directory|The directory in which the temporary files are stored in case when needed; the default is the standard temporary directory for the system
|TMP-file prefix|Choose an easily recognized prefix so you can identify the files when they show up in the temp directory.
|Sort size|The more rows you store in memory, the faster the sorting process because fewer temporary files must be used and less I/O is generated.
|Free memory threshold (in %)|If the sort algorithm finds that it has less available free memory than the indicated number, it will start to page data to disk.
|Compress TMP Files|Compresses temporary files when they are needed to complete the sort.
You can also give a variable: when it is set, its value (Y or N) decides whether the files are compressed.
|Compression level|How hard to compress the temporary files: 1 - Fastest, 2 - Very fast, 3 - Fast, 4 - Balanced, faster, 5 - Balanced, 6 - Standard (the Java default), 7 - Smaller files, 8 - Very small files, 9 - Smallest files.
Temporary files are read back only once, so a low level is usually best.
A new transform uses 1 - Fastest. A transform saved before this option existed keeps 6 - Standard, the level it always used.
|Only pass unique rows?|Enable if you want to pass unique rows only to the output stream(s).
|Fields table|Specify the fields and direction (ascending/descending) to sort.
You can specify whether to perform a case sensitive sort (optional)
|Get Fields|Click to retrieve a list of all fields coming in on the stream(s).
|===
