= Run, Preview and Debug a Pipeline

== Running a Pipeline

Running a pipeline to see how it performs can be done by completing one of the following tasks:

* Using the Run image:getting-started/icons/run.svg[Run,25px,align="bottom"] icon
* Select Run and Start execution from the top menu
* Pressing F8

In the pipeline run dialog, hit the 'New' button in the upper right corner to create a new 'Pipeline run configuration'.

image::run-configuration/configuration-selection.png[Hop Configuration Selection,45%,align="left"]

In the dialog that pops up, add 'Local Pipeline' as the pipeline configuration name and choose the 'Local pipeline engine' as engine type.

image::hop-gui/pipeline/run-configuration-pipeline.png[Run configuration pipeline,75%,align="left"]

Click 'Ok' to return to the pipeline run dialog.

Choose the logging level as described below.

[width="85%",cols="30%, 70%",options="header"]
|===
|LogLevel|Description
|Nothing| Do not record any logging output.
|Error|Only record errors in logging output.
|Minimal|Only use minimal logging.
|Basic|This is the default logging level.
|Detailed| This logging level gives a detailed logging output.
|Debugging|Results in a very detailed output for debugging purposes.
|Row Level|Logging at row level.
|===

If the pipeline has parameters, give them a value on the *Parameters* tab of this dialog, or leave the value empty to use the default value. See xref:variables/parameters.adoc#_from_hop_gui[Working with parameters].

Make sure your configuration is selected and hit 'Launch'.

When a pipeline has run successfully, a check mark is displayed in the upper right corner of each transform. With more than one copy, that check is shown only when every copy of the transform has finished. Until then the corner shows how many copies are done. See xref:pipeline/specify-copies.adoc#finished-copies[Specify copies].

image::hop-gui/pipeline/executed-pipeline.png[Executed pipeline,75%,align="left"]

The transforms also show a little table icon, giving you access to a preview of the results of that transform.

image::hop-gui/pipeline/preview-pipeline.png[Preview pipeline,75%,align="left"]

When a pipeline fails, a red triangle is shown in the upper right corner of the failed transform.
Hover your mouse over the red error triangle to take a quick peek at the error message. The full stacktrace is available in the logs. Check xref:pipeline/errorhandling.adoc[pipeline error handling] to learn about how you can handle errors in your pipeline gracefully (which is not necessarily what you want).

image::hop-gui/pipeline/failed-pipeline.png[Failed pipeline,75%,align="left"]

[[execution-results]]
After each run the execution results are displayed in the panel on the bottom of your window.
The panel has these tabs:

* *Logging*: the log of the pipeline.
* *Metrics*: the metrics of each transform.
* *Problems*: the results of the checks of the pipeline and of the linter.
* *Revisions*: the git history of the pipeline file, when Git is enabled.

The same tabs are shown for a workflow, see xref:workflow/run-debug-workflow.adoc[Run and Debug a Workflow].

=== Problems

When the xref:linting/index.adoc[linter] is installed and switched on, the Problems tab lists its findings for the file as soon as the file has been linted: when you open it, when you save it, and shortly after you stop editing.
*Verify this pipeline* on the toolbar adds the remarks of Hop's own checks next to them.
Double-click a remark to open the transform it is about.
The toolbar of the tab can collapse and expand all remarks, and *Force refresh* clears the database cache and checks the pipeline again.

image::hop-gui/pipeline/problems-pipeline.png[Problems pipeline,75%,align="left"]

=== Revisions

The Revisions tab lists the commits of the pipeline file, with the columns *Message*, *Author*, *Date* and *Commit*.
It is shown when *Enable the git plugin* is on (see xref:hop-gui/hop-gui-git.adoc#_git_configuration_options[Git Configuration options]) and Hop has found a git repository for the project, see xref:hop-gui/hop-gui-git.adoc[Working with git].
For a file that isn't saved yet, that is outside the git repository, or that has no commit yet, the tab shows a message instead of the list.

Select a commit and use *Show text diff* or *Show visual diff* on the toolbar of the tab to compare that version with the file as it is saved now; double-clicking a commit also shows the text diff.
When the pipeline has changes that aren't saved yet, Hop warns that the comparison is made with the last saved version.

== Preview and debug a pipeline

To inspect pipeline data while controlling how execution pauses, use **Preview & debug** (toolbar, Run menu, or transform actions). This opens a single dialog for preview rows and optional breakpoint behavior.

You can start it in any of these ways:

* Using the preview image:getting-started/icons/view.svg[Preview,25px,align="bottom"] icon on the pipeline toolbar
* Select **Run** and **Preview & debug** from the top menu
* Select **Preview & debug output** from the transform action menu
* Click on the tiny bottom right icon after running the pipeline

image::hop-gui/pipeline/preview-menu-pipeline.png[Preview Menu pipeline,75%,align="left"]

In the dialog, choose the transform whose rows you want to inspect.
Set how many rows to retrieve (**Retrieve first rows**), and optionally enable **Pause on breakpoint** and define a **condition** so the pipeline pauses when that condition matches a row.
When finished press **Quick Launch**.
To change the pipeline run configuration, click **Configure**.

The collected rows are shown in the preview window when execution pauses or finishes.

image::hop-gui/pipeline/preview-pipeline.png[Preview pipeline,75%,align="left"]

== Table views

Preview windows (and other table grids in Hop Gui) can contain a large number of columns.
A **table view** is a named subset of those columns, in the order you want to see them.
Hidden columns stay in the data and are still exported, copied or saved.
A view can also carry filters on its columns: rows that do not match are hidden while the view is applied, and come back with **Show all columns**.
Row filters are offered when browsing data, such as **Show rows**.
A grid that edits configuration leaves **Add filter** and **Remove filter** disabled and does not hide rows for a saved filter, so confirming the dialog still keeps every row.

Open the **Table views** dialog from the table toolbar image:getting-started/icons/view.svg[Table views,25px,align="bottom"] icon, from the row context menu, or from the column header context menu.

image::hop-gui/pipeline/table-views-dialog.png[Table views dialog with an applied column filter,75%,align="left"]

In the dialog:

* The dialog opens with every column in **Columns in view** (columns on screen first, then the rest) and with any filters already applied from the column header. **Use current layout** copies the columns that are visible now.
* Move fields between **Available columns** and **Columns in view**, and use the **arrow up** and **arrow down** buttons in the middle to set the display order.
* **Add filter** picks a column and then shows the unique sorted values of that column, where you select the values to keep. An `<null>` entry covers empty values. The filter shows up as `Column-Name : value1,value2,value3` in the **Applied filters** list, and **Remove filter** takes the selected filters out again.
* A column with more than 500 unique values asks for confirmation before the values are listed.
* **Apply** shows only the selected columns, in that order, and hides the rows that do not match the applied filters. Filtered columns get a filter icon in their header.
* **Show all columns** restores the full table: every column and every row comes back.
* **Save** stores the view, including its filters, so you can reuse it later.

Views are stored per project in the Hop audit folder and are matched by column name.
A view such as `customer-bk-fields` can be applied to any table that has those field names, not only the preview where you created it.

The column header context menu can hide that column, add a filter on it, or remove the filter it already has.
**Remove filter** stays disabled until that column has a filter.

image::hop-gui/pipeline/column-header-filter-menu.png[Column header menu with Add filter,40%,align="left"]

**Add filter** lists the unique sorted values of that column, the same way the dialog does.
Select the values to keep and press **OK**.

image::hop-gui/pipeline/column-filter-values.png[Filter values for the table-name column,75%,align="left"]

The filter is applied straight away.
The column header shows a filter icon, and only the matching rows stay visible.

image::hop-gui/pipeline/column-filter-applied.png[Rows filtered to one table name,75%,align="left"]

You can also drag headers to reorder them (desktop Hop Gui).
Those one-off changes can be captured with **Use current layout** and then saved as a named view.

The table toolbar itself can be turned on or off with **Show a toolbar above tables** in the xref:hop-gui/perspective-configuration.adoc[Configuration] perspective.
