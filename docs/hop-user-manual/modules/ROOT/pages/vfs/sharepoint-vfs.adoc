= Microsoft SharePoint VFS

== Scheme

There is no fixed scheme.
Every xref:metadata-types/sharepoint-connection.adoc[SharePoint Connection] registers a scheme with its own name, so a connection named `m365` gives you:

`**m365://**`

The credentials are stored in the connection, never in the path.

== Configuration

Create a xref:metadata-types/sharepoint-connection.adoc[SharePoint Connection] in the metadata perspective.
The application it signs in with needs the Microsoft Graph application permission `Sites.Read.All` to read files, or `Sites.ReadWrite.All` to also write them.

== Usage and testing

The path has three parts: the site, the document library, and the path of the file or folder in that library.

`+m365:///<site>/<library>/<folder>/<file>+`

[options="header",cols="2,3"]
|===
|Path|What it is
|`+m365:///+`|The SharePoint sites of the tenant
|`+m365:///Finance+`|The document libraries of the site `Finance`
|`+m365:///Finance/Documents+`|The root folder of the library `Documents`
|`+m365:///Finance/Documents/reports/2026/daily.csv+`|A file in that library
|===

* The site is the name of the site as it appears in its URL (`Finance` for `+https://contoso.sharepoint.com/sites/Finance+`).
* The library is the name of the document library.
The default library of a site is named `Documents` on an English tenant, even though its URL says `Shared Documents`.
* Site and library names are not case-sensitive.
When two sites have the same name, the one under `/sites` is used rather than the one under `/teams`.
* With the permission `Sites.Selected` the root `+m365:///+` is empty, because the application can not list the sites. Set the SharePoint host on the connection and enter the path of a site it was granted, such as `+m365:///Finance+`.

You can browse the sites, libraries and files in the xref:hop-gui/vfs-file-explorer.adoc[VFS File Explorer] or in any file dialog.

== Microsoft Teams channels

The files of a Microsoft Teams team are stored in a SharePoint site, so they are reached with the same paths.
Where the files of a channel are depends on the type of the channel.

[options="header",cols="1,2,3"]
|===
|Channel|Site|Path
|Standard|The site of the team|`+m365:///<team>/Documents/<channel>/<file>+`
|Private or shared|A site of its own, usually named `<team>-<channel>`|`+m365:///<team>-<channel>/Documents/<channel>/<file>+`
|===

* A channel is a folder of the library `Documents`, never a site or a library by itself.
The folder of the default channel is named `General`.
* The name of the site of a team is not always the name of the team.
To find the exact names, open the *Files* tab of the channel in Teams and choose *Open in SharePoint*: the site is what follows `/sites/` or `/teams/` in the URL, the folder is what follows `Shared Documents/`.
* Do not put `/sites` or `/teams` in the path, only the name of the site.
* With the permission `Sites.Selected`, the site of a private or shared channel has to be granted to the application separately from the site of the team.

== Limitations

* Sites and document libraries can be listed but not created, renamed or deleted.
* Appending to a file is not supported.
* A file or folder can only be renamed or moved inside its document library.
Moving it to another library or site copies the content and deletes the original.
* A file is buffered in a local temporary file while it is written and is sent to SharePoint when it is closed.
Files larger than 4 MB are sent in slices through an upload session.
