= Contributing changes

Apache Hop is developed by an open community, and contributing goes well beyond writing code.
The project's contribution guides live on the website and are the authority on process:

* https://hop.apache.org/community/contribution-guides/code-contribution-guide/[Code contribution guide]
* https://hop.apache.org/community/contribution-guides/code-review-guide/[Code review guide]
* https://hop.apache.org/community/contribution-guides/documentation-contribution-guide/[Documentation contribution guide]
* https://hop.apache.org/community/contribution-guides/translation-contribution-guide/[Translation contribution guide]
* https://hop.apache.org/community/contribution-guides/release-contribution-guide/[Release contribution guide]

link:https://github.com/apache/hop/blob/main/CONTRIBUTING.md[CONTRIBUTING.md] in the repository root collects those links along with the ICLA requirements and how one becomes a committer.

This page is about the mechanics on the code side.

== Before you open a pull request

* There is a https://github.com/apache/hop/issues[GitHub issue] for the change, and the pull request references it.
* `./mvnw spotless:apply` has been run.
* Every new file carries the Apache License 2.0 header, or RAT will fail the build.
* The build passes locally — see xref:build-and-test.adoc[Building and testing].
* New behaviour has a test. xref:testing/unit-testing.adoc[Unit tests] for logic, xref:integration-testing.adoc[integration tests] for anything that needs a pipeline to actually run, xref:testing/ui-testing.adoc[UI tests] for dialogs and widgets.
* User-visible behaviour has documentation — see xref:writing-documentation.adoc[Writing documentation].

== Getting help

Questions are welcome on the https://hop.apache.org/community/mailing-list/[mailing lists], in https://github.com/apache/hop/discussions[GitHub Discussions], and on Slack.
For a change large enough that you would rather not build it twice, ask on the dev list before starting.
